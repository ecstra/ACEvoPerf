# Reflex

Assetto Corsa EVO has no Reflex support. The mod adds it through NVAPI from inside the
`dstorage.dll` proxy, using the swap chain's D3D12 device, and sleeps once per frame after
the real `Present` returns, which is the only frame start a proxy can see. It never caps the
frame rate: `minimumIntervalUs` is hard coded to zero, so this is not a limiter.

## It works

The driver says so, not just our own counters. `NvAPI_D3D_GetSleepStatus` is queried twice:

```
[reflex] the driver reports right after enabling it:   low latency mode off
[reflex] the driver reports after a thousand frames:   low latency mode ON
```

The first query is always too early to mean anything, the driver does not report the mode
active until frames actually flow through it. The second is the real answer, and it read ON in
every run with `reflex=1`, with zero refused sleep calls across thousands of frames.

## It changes nothing measurable here, and the reason is the machine

Four runs of two laps each at the Nurburgring GP, same car, mod 0.3.1 plus this branch,
windowed to the driving and excluding the track load:

| run | reflex | boost | avg fps | median ms | 1% low | 0.1% low | p99/median |
|---|---|---|---|---|---|---|---|
| C | off | n/a | 82.1 | 12.15 | 57.6 | 37.7 | 1.31 |
| A | on | off | 80.5 | 12.27 | 56.2 | 31.8 | 1.29 |
| A2 | on | off | 80.2 | 12.32 | 56.7 | 33.9 | 1.29 |
| B | on | on | 77.8 | 12.72 | 56.1 | 35.0 | 1.28 |

Runs C and A2 are the only pair with GPU telemetry alongside, taken back to back:

| run | GPU clock | power | temp | GPU utilisation |
|---|---|---|---|---|
| C, reflex off | 1568 MHz | 91.9 W | 86.5 C | 96.7% |
| A2, reflex on | 1549 MHz | 89.6 W | 86.3 C | 97.0% |

The two facts that matter are in that second table. **The card sits at 86 to 87 degrees for the
whole of every run**, from the first sample, and holds there while the clock falls from
1705 MHz to about 1510 over two laps. Temperature never moves because the thermal limiter pins
it and pays for it in clocks. And **the GPU is 97 percent utilised**.

A machine in that state is GPU bound and thermally capped. Its frame rate is decided by how
many megahertz the cooler will allow, and nothing on the CPU side can add any. Reflex works by
stopping the CPU queueing frames further ahead than the GPU can use, so on a GPU that is
already the bottleneck it has almost nothing to do. The 2.4 percent between C and A2 is largely
the 1.2 percent clock difference between them, and the rest is inside the run to run drift of a
card whose clocks fall 190 MHz over two laps.

So the honest result is not "Reflex is slower". It is that this machine cannot show a Reflex
difference either way, and the frame rate was never what Reflex was for.

## What was not measured

Latency. Reflex reduces the age of the input behind a frame, which is its entire purpose, and
none of these runs measured it. `NvAPI_D3D_GetLatency` would report the driver's own figures
and was not wired up. Frame rate being flat is the expected outcome of a working Reflex
integration, not evidence against one.

## Boost

Unresolved by measurement and closed by reasoning. Run B is the only boost run and it has no
GPU telemetry, and it started ninety seconds after run A ended on a card already at 62 degrees
idle, so its 77.8 fps is not attributable to boost.

It does not need another run. Boost exists to stop the GPU dropping clocks while it waits.
This card never waits: it is at 97 percent utilisation and its clocks are limited by heat, not
by a power saving state. There is no clock for boost to keep up, so it has nothing to give here
and can only add watts to a card that is already converting every available watt into heat it
cannot shed. On a desktop with thermal headroom the trade is different, which is why it stays
available.

## Restart check

If this is ever revisited, the machine to revisit it on is not this one. It needs a card with
thermal headroom that is not at 97 percent utilisation, and it needs
`NvAPI_D3D_GetLatency` wired up so latency is measured instead of inferred. On the reference
laptop the only honest experiment left would be at a much lower resolution or detail level,
where the GPU stops being the bottleneck and the CPU side starts to matter.
