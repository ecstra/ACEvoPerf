# Ghost car

Tried and dropped on 2026-09-06 on 0.9.0+release.48 (DEC-012). The game has no ghost car in
the release build, only the delta timer against the best lap. The flag `ghostcar_enabled`
("enable ghost car", registered in `PlatformCore.cpp`) switches on a recorder and a player
that are complete on the data side and have no presentation side. This doc is what was found,
so nobody flips the flag again expecting a car.

## What runs with the flag on

All of it was seen in one run: three laps on the Red Bull Ring GP layout in a Ferrari 296 GT3
in solo practice, back to the menu, the same car and layout again, one more lap.

- **Creation.** In the session setup (`initializeWorld`, the function around RVA 0x1329dc0)
  PlatformCore allocates a 0xd08 byte ghost data object into its member at +0x1f0 when the
  flag is set and the slot is empty. The object holds two strings, a vector of 32 byte
  frames (a quantised position and rotation per frame), a clock at +0xce8, a duration at
  +0xce0 and the lap time at +0xcc8.
- **Record and save.** Every finished lap the platform layer broadcasts
  `NewGhostCarAvailable { laptime }`. Its handler (RVA 0x132f990) copies the lap out of the
  replay recorder into the ghost data and marks it dirty, the next tick saves it through the
  replay code: `[replay] Saving ghost cars`, then `Replay saved ACEVO__<car>_<layout>`. The
  file is `Saved Games\ACE\GhostCar\ACEVO__ks_ferrari_296_gt3_GP.ghost`, 44 KB for a 1:34
  lap, and each better lap overwrites it. The empty piece between the two underscores is a
  field that stays empty in this build.
- **Load.** In the `onGameCarCreatedEvent` handler (RVA 0x132e630), when the created car is
  the player's and the flag is set, the same name is built and the file read:
  `[replay] Loading ghostcar ACEVO__ks_ferrari_296_gt3_GP`, then `Replay loaded`. A broken
  file logs `Error loading ghostcar %s` and sets the lap time to minus one.
- **Play.** PlatformCore's per frame update (RVA 0x1333800) calls the ghost tick (RVA
  0x198bd90) with the frame time: it advances the clock, wraps it to zero past the recorded
  duration, and samples the frame at the current time (RVA 0x198c060) into a car pose object
  that lives inside PlatformCore itself at +0x1f8, a 4 by 4 transform and a few interpolated
  floats. The clock starts at the load, it is not synchronised to the player's lap.

## Where it stops

Nothing reads that pose. Checked three ways:

- Every function in the PlatformCore code range that touches +0x1f0 or +0x1f8 is the
  constructor, the destructor, the setup, the tick, the two save and load paths and the
  small copy wrapper behind the `bool (PlatformCore::*)(GhostCarData&)` binder.
- A scan of the whole `.text` for code touching the pose's matrix rows at PlatformCore's
  offsets found only unrelated objects with the same layout and two field by field struct
  copies.
- The vehicle system (`ksPlatformClient\VehicleSystem.cpp`) knows `ClientCarType_PhysicsCar`
  and `ClientCarType_Netcar`, and a replay vehicle source used by the replay viewer. No ghost
  type, no spawn from a live session, no ghost material or shader, no ghost strings anywhere
  but the recorder and loader, and the UI scripts (all 25 files under `uiresources`) have no
  ghost element. The only ghost related message reaching the UI is `NewGhostCarAvailable`,
  which the UI does not handle.

So the flag makes the game write ghost files it never shows. More laps, other modes or a
hotlap event do not change that, the consumer is not in the exe.

## What it would take

A ghost would need a car on track fed from that pose every frame: a replay source vehicle
spawned next to the player through the vehicle system's internal C++ interface, kept alive
across the session, and told each frame where the ghost is. That is engine work from inside
the proxy, not a flag, and it was not started.

## Restart check

On a new game version, before anything else: look for a third `ClientCarType_` string, for a
`SpawnVehicle` with a replay or ghost source in a live session log, or for a reader of the
pose behind PlatformCore's ghost data pointer. If one of those exists, the flag is worth one
more two session test exactly as above. The ghost file format is the replay recorder's frame
list, so a saved `.ghost` from 0.9.0 says nothing about a later build.
